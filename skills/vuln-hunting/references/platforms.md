# 平台规则与授权边界

## 补天（butian.net）

国内最大的漏洞众测平台之一。分**公益 SRC**（厂商免费入驻，白帽自由测试）和**企业 SRC / 众测项目**（有明确周期和范围）。

**公益 SRC 的特性**：
- 范围通常是**厂商自行提交的资产清单**，粒度粗，经常只写一个主域名
- **默认不含子域名**，除非明确列出——这是最常见的越界点
- 奖励以积分/rank 为主，现金少
- 厂商响应质量参差，很多长期不处理

**企业众测项目**：有明确起止时间、明确资产清单、明确禁测项。**以项目页面为准**。

## 漏洞盒子（vulbox.com）

定位类似，同样有公益 SRC 和企业众测。规则口径与补天大同小异，具体以项目页为准。

---

## ⛔ 授权边界三原则

1. **白名单思维**：只碰项目页面**明确列出**的资产。没列的一律视为范围外，哪怕它明显属于该厂商。
2. **子域是最危险的地方**：公益 SRC 大量项目只授权主站。`a.example.com` 和 `b.example.com` 可能是完全独立的业务系统，扫它 = 未授权。
3. **不要碰旁站和 C 段**：同一 IP 上的其他站点不属于该厂商。

### 越界的后果

| 行为 | 后果 |
|---|---|
| 扫了范围外子域 | 判违规，扣 rank / 警告 |
| 扫了同 IP 旁站 | 可能被投诉，封号 |
| 造成目标不可用（无速率限制 / DoS） | 封号 + 可能承担法律责任 |
| 导出真实业务数据证明危害 | 即使授权范围内也可能违规——**证明危害用最小 PoC，不要真拖库** |

## 哪些洞值得花时间

公益 SRC 里**早就被刷烂**的（除非目标很冷门，否则别浪费时间）：

- 信息泄露（`.git`、`.svn`、备份文件、phpinfo）
- CORS 配置错误
- SPF/DMARC 缺失
- 任意文件读取（无敏感内容）
- 无危害的反射型 XSS
- 版本号泄露类"漏洞"

**性价比更高的方向**：

| 方向 | 为什么 |
|---|---|
| **越权 / 水平权限** | 自动化扫不出来，全靠理解业务，重复率低 |
| **逻辑漏洞** | 支付、优惠券、积分、审批流——同上 |
| **未授权访问的 API** | 前端 JS 里翻接口，很多后台接口没鉴权 |
| **SSRF** | 直达内网，危害大，评分高 |
| **SQL 注入** | 传统但评分依然高 |
| **供应链 / 第三方组件** | 一个组件问题影响多个资产 |

**结论**：工具负责找"面"，人负责找"点"。真正值钱的洞基本都在工具够不着的地方。

## 报告格式

平台打回报告最常见的原因：**只有截图，没有复现步骤**。

一份能过的报告包含：

```markdown
## 漏洞标题
<类型> - <资产> - <一句话影响>          # 例：越权访问 - api.xxx.com - 可查看任意用户订单

## 资产
<完整 URL / 接口>

## 漏洞类型
<越权 / SQL 注入 / SSRF / 逻辑漏洞 ...>

## 复现步骤
1. 登录 A 账号（test_a / 已注册）
2. 访问 <URL>，抓包得到请求：
   ```
   GET /api/order/detail?id=1001 HTTP/1.1
   Host: api.xxx.com
   Cookie: <A 账号的 cookie>
   ```
3. 将 id 改为 1002（属于 B 账号）
4. 返回 B 账号的完整订单信息 → 越权成立

## 危害说明
<能拿到什么、影响多少用户、能否进一步利用>

## 修复建议
<针对性的，不要写"加强权限校验"这种废话>

## 证据
<请求/响应原文，敏感信息打码>
```

**要点**：
- 标题写清"什么资产 + 什么洞 + 什么影响"，审核第一眼就看这个
- 复现步骤要**换个人能重现**，包括账号怎么注册
- 证据贴**原始请求响应**，不要只贴截图（截图无法验证）
- **敏感数据打码**——证明能拿到即可，不要把真实用户数据贴上去

---

## 提交前必做：查重

公益 SRC 重复率极高。提交前：

1. 在平台搜目标域名 + 漏洞类型
2. 评估该厂商历史报告的常见类型（很多厂商被刷了几百遍）
3. 想清楚**你的报告和已有的有什么不同**

被判重复不扣分，但浪费时间且拉低有效提交率。

---

## 反面案例：不要批量自动提交

目录里收录了 `int-wc/VulBoxAuto`（漏洞盒子批量提交脚本），**明确不推荐使用**：

- 批量自动提交是平台**明确打击**的行为
- 产出质量低 → 大量被判无效/重复 → 账号信誉分下降
- 严重的直接封号

自动化应该用在**发现阶段**（资产收集、扫描、去重），**提交阶段必须人工**。
